# Clarity 巡检指南

用 Microsoft Clarity 回放 + 洞察数据发现产品体验问题的方法。**巡检只负责发现和记录问题：发现问题开 GitHub issue，不在巡检过程中顺手改代码。**

## 项目与访问

- 后台：<https://clarity.microsoft.com/projects/view/zh74gh2cce/dashboard>（项目名 MuiStory）
- 前端集成：`packages/app/src/components/Clarity.tsx`，构建期变量 `NEXT_PUBLIC_CLARITY_ID`
- Clarity 自动采集点击/滚动/路由，无需埋点；数据有延迟，新版本上线后约几分钟到数十分钟开始出现新数据

## 巡检流程

### 1. 仪表盘概览（Overview，默认最近 3 天）

先看四个核心指标，再看 Insights 四张卡：

| 指标 | 关注点 |
|---|---|
| Sessions / Unique users | 样本量。**< 20 会话时只看绝对数，不要看百分比结论** |
| Pages per session | 是否有人在浏览站内链路 |
| Scroll depth | 首屏内容是否被消费 |
| Active time | 2.9/5.5 min 这类"活跃/总时长"比例，反映 tab 切换频繁度 |

Insights：Rage clicks / **Dead clicks** / Excessive scrolling / **Quick backs**。
另外看 Performance（LCP/INP/CLS）、Top pages、Referrers、Browsers、JS errors。

### 2. 洞察下钻

- 左侧导航（折叠在 Dashboards 下）有 Rage clicks / Dead clicks / Quick backs / Clicked text / JavaScript errors 明细页
- 数据少时明细页信息有限，直接跳到回放看过程

### 3. 回放分析（Recordings）

- 列表按 `Entry / Exit / Duration / Clicks / Pages / User ID` 快速筛选可疑会话：**时长极短 + 点击多 + 页面多 = 卡壳**；**时长长 + 点击多 = 最丰富的行为样本**
- 打开回放 → `More details` 打开事件时间线，逐条读事件重建用户行为链

### 4. 代码验证

时间线事件 + 代码 grep 互证后再下结论。例：回放显示"点返回游戏库 → 落地首页 → 2 秒 quick back"，再 grep `backToLibrary` 发现 `href="/"`，才能确认是链接目标错误而不是偶发行为。

## 时间线事件词汇表

| 事件 | 含义 / 判读 |
|---|---|
| `Page visit: <url>` | 页面到达（含 SSR 首屏与客户端路由）。无 click 事件时出现，通常是浏览器后退/前进（移动端手势/返回键不产生 click） |
| `Click: "<文本>"` | 点击。文本是最近的可访问名称；移动端 tap 的文本归属可能不准，不要过度相信 |
| `Dead click` | 点击后短时间内无任何页面/交互响应。两类常见：**水合前点击被吞**、**静态元素被误认为可交互** |
| `Quick back click` | 进入某页后 1–2 秒内退回上一页。多半是**目标页与预期不符**（链接指向错误、内容空、加载失败） |
| `Resized page` | 移动端地址栏收起/展开、旋转；不是用户行为，忽略 |
| `Page hidden` | tab 切后台/离开，会话接近结束 |
| `Expand details` | 点开某事件的细节，可看坐标、元素、目标 URL |

## 指标解读注意

- **死点击/快速返回的百分比分母是会话数**。6 会话里 3 个死点击 = 50%，看起来吓人但绝对值只有 3
- **LCP/INP/CLS 是真实用户数据**，样本个位数时单点异常会拉爆均值；先看样本量（"from N pageviews"），再看 URL 分布
- **Bot sessions 不计入总数**（卡片上单独标注）
- Clarity 的 URL 明细、Funnels 等高级卡片在样本不足时不渲染，不要误判为故障

## 问题 → Issue 规范

巡检产出物是 issue，不是 commit。创建时遵循既有标题习惯：

```
[P?][类别] 一句话结论
```

类别示例：`[UX]`、`[Perf]`、`[SEO]`、`[调查]`。正文必须包含：

1. **背景**：巡检日期、样本量
2. **证据**：回放 ID/用户 ID + 时间线片段（带时间戳）
3. **推断**：多种可能原因，标明置信度
4. **建议方向**：下一步排查动作
5. **验收**：可观测的成功标准（Clarity 指标 / GA4 事件）

## 已沉淀的判定模式

| 现象 | 常见原因 | 验证方式 |
|---|---|---|
| 同一目标连点 2–3 次才生效 | 水合前点击被吞（慢网络/低端机） | 时间线上点击时间差 <3s + 页面刚加载；本地 throttle 复现 |
| 点击 → 7 秒后 Dead click | 同上，点击后无响应直到用户再点 | 看点击间隔与首个 Page visit 的时间差 |
| 点击某目标 → 1 秒内返回 → 再点同一目标 | 首次点击疑似未生效（加载/水合慢）或落地页异常，用户重试 | 对照两次点击的目标是否相同；看重试后是否成功 |
| 反复点击标题/简介文字后 Dead click | 可点击区域过小或文字看起来可点但不可点 | 对照页面实现，检查点击热区是否覆盖用户直觉目标 |
| 进入详情页 → 进 /play → 2 秒内退回 | play 标题页首屏内容/CTA 与预期不符；或误点 | 对比该用户正常游玩的游戏与秒退的游戏标题页差异 |
| 点击静态图形（进度条/属性条）判 Dead click | 元素看起来可交互但无交互 | 对照游戏 UI 实现，确认该元素无 onClick |
| 进入页面 1–2 秒内退回 | 链接目标错误 / 页面内容不符预期 | 回放定位点击元素 → 查该链接 href |
| 列表 → 详情 → 返回，每次停留 3–8 秒，反复多次 | 用户在快速筛选内容；详情页决策信息不足或缺直接开玩入口 | 看详情页均值停留与详情→游玩的转化率 |
| 每页停留 1–20 秒 + 连续 quick back，按导航顺序遍历全站 | **全站快速评估型用户**（调研/比价/测评），非缺陷 | 看是否按 nav 顺序访问多个营销页；停留短但每页都有点击 |
| 长时间停留（>3min）+ 0 点击 | 页面未就绪/不可交互（重组件、移动端水合慢），或用户挂后台 | 看 active time 与页面类型；对比同页其他会话；优先查重页面（编辑器）的移动端性能 |
| 同一 URL 反复出现且无点击 | 移动端返回键/手势后退 | 无 click 事件 + 相邻 Page visit 成对出现 |
| 时长 ≤1s + 0 点击 + 1 页面 | **可执行 JS 的爬虫/链接预览**（Clarity 未必标为 bot），或极快 bounce | 看入口 URL 是否分散、是否有 referrer；占比高时先剔除再算转化率 |
| 登录成功后访问 /my/dashboard 被弹回首页 | 会话态竞态（useSession 缓存未失效）或路由竞态，机制待复现（#35） | 按 issue 复现步骤验证；留意是否有点击事件（无点击 = 程序跳转） |
| JavaScript errors 卡片显示 100% script error | 跨域脚本抛错且无 CORS 头，浏览器不提供堆栈 | 点卡片内「Recordings」按钮过滤出对应会话，看错误所在页面；长期方案是自建 `window.onerror` 上报 |

**定位 JS 错误会话的快捷方式**：JavaScript errors 卡片 → 卡片内 `Recordings` 按钮 → 会话列表被过滤（URL 带 `ScriptErrorText` 参数）→ 打开会话看 Event timeline 的按页面事件分组（如 `Visited: /play/xxx  01:11  Events: 16 Click / 3 JavaScript error`），可精确定位到出错页面与时间窗。

每次巡检结束追加一行，用于判断趋势（窗口均为"最近 3 天"）：

| 日期 | 会话/用户 | pages/会话 | 死点击 | quick back | LCP | INP | CLS | 备注 |
|---|---|---|---|---|---|---|---|---|
| 2026-11-22 | 6 / 5 | 5 | 50%（3） | 33%（2） | 28 s | 140 ms | 0.038 | 基线 |
| 2026-11-24 | 19 / 17 | 3 | 15.8%（3） | 26%（5） | 4.4 s | 210 ms | 0.001 | 流量 3 倍 |
| 2026-11-25 | 18→31 / 15→26 | 3.44 | 5.6%→12.9% | 33%→35.5% | 2.3→2.5 s | 140→210 ms | 0.025 | 日内两次读数；首次出现 3 个 JS 错误 |
| 2026-11-27 | 23→29 / 22→28 | 3.30→4.03 | 21.7%→20.7% | 34.8%→34.5% | 3.9→2.5 s | **540 ms（poor）** | 0.11→0.088 | 移动端占比 ~30%；INP 连续两轮 poor；JS 错误无新增；首次出现编辑器会话 |

判读注意：quick back 的绝对数随流量增长而增加是正常的；关注其**构成**（坏链 vs 主动抽样浏览）而不是只看百分比。2026-11-25 起流量以桌面 Chrome/Edge + 搜索引擎（bing/google）为主。

## 历史案例

- **2026-11-22**：回放发现「返回游戏库」指向 `/` 而非 `/games`（EndScreen + TitleScreen ×2），用户每次通关都要 quick back 再手动去游戏库；同时发现 my/admin 登录墙不带 `redirect`，登录后回首页丢失意图。修复 commit `381ac9f`。
- **2026-11-22**：死点击 50%、LCP 28s（n=1）、AI 直链落地 0 点击 → 记录为 issue #31 / #32 / #33，留待数据积累后复核。
- **2026-11-24**：流量 3 倍增长（19 会话，cn.bing/google 进站）。抽查 quick back 会话均为**主动抽样浏览**（游戏详情页 3–8s 进出、定价页 7s），新增回放中未再出现「返回游戏库→首页」模式，初步验证 `381ac9f`。新发现：42%（8/19）会话为 1s/0 点击（疑爬虫/预览）；游戏详情页筛选循环 → issue #34；详情页性能更新到 #32、直链落地证据补充到 #33。
- **2026-11-25**：性能全面达标（LCP 2.3s / INP 140ms / 综合 86，#32 可关闭）；死点击降至 5.6%，且全部集中在游戏详情页标题/简介文字被点（#34 证据增强）。新发现登录后访问 /my/dashboard 被弹回首页（1fzjqy4 回放，机制不明）→ issue #35。高价值样本：UAE 用户 1fzjqy4 两次会话共 25+5 点击，展示了「列表→详情→游玩→返回」完整路径与 OTP 登录流程。
- **2026-11-25（二次巡检，31 会话 / 26 用户）**：首次出现 JS 错误（3 个，100% script error），用「卡片内 Recordings 过滤」定位到唯一会话 1bo5qev：错误全部集中在**首页精选游戏 zhumadian-exorcist 游玩页**（71 秒 16 点击 + 死点击 + 快速返回）→ issue #37。登录漏斗：3 个会话止步 `/sign-in?redirect=/my/dashboard`（Submit form 3 / Login 1）→ issue #36；`/sign-in?redirect=...` 作为入口/出口 URL 出现，确认 11-22 redirect 修复生效。直链落地 /play 再 +3 例（累计 8，含 10s/13s 停留）。
- **2026-11-27**：性能三项回退（LCP 3.9s / **INP 540ms poor** / CLS 0.11），移动端占比从 ~14% 升至 ~30%，疑为低端设备 + 慢网络所致（样本 13 pageviews）→ #32。JS 错误无新增（仍是 11-25 的会话）。登录漏斗恶化：Submit form 3 / Login 0 → #36。出现 **gemini.google.com** 来源（AI 引擎推荐流量）；`/play/zhumadian-exorcist` 成为访问量最高的游玩页（3/22）。发现「全站快速评估型」用户 xn5xwa：1:51 内按导航顺序遍历 11 个页面、10 次 quick back，最后在 /create 停 8 秒离开——quick back 的高占比主要由这类浏览习惯贡献，不是坏链。
- **2026-11-27（二次读数，29 会话 / 28 用户）**：INP 仍 540ms poor（连续两轮同值，LCP/CLS 已恢复 good）；登录漏斗 Submit form 4 / Login 0，`/sign-in` 访问 7 次 → #36 升级关注。首次捕捉到创作漏斗会话：128x851（China / Edge Mobile，14:57、**137 点击、33 页面**，入口 /create）证明移动端有强创作意图；ttr4kv（ChromeMobile，/my/edit/284 **9 分钟 0 点击**后跳 sign-in?redirect）→ 新建 #38 移动端编辑器不可交互调查。`/my/edit` 首次出现，redirect 修复在编辑器守卫生效。注：本轮 Clarity 播放器无法通过自动化打开（卡片点击失效），分析基于会话元数据。
